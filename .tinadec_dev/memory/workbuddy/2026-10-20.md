## "关于"页粒子瀑布（设计 + 试验台，未接入 AboutSection）

用户要的：把 About 页从三层圆角盒子里放出来、铺满右侧详情区，背景是**粒子**做的瀑布（不是模糊/水墨，要颗粒可数），上段湖面波浪翻滚、越过水沿后飞流直下；粒子色跟随主体色，鼠标可交互；浅色模式用白粒子。

**环境硬约束**：本轮外网全断（npmjs / npmmirror / unpkg / github 全部 ECONNRESET 或超时），`npm i three` 装不上。改为**手写原生 WebGL2**（`apps/desktop/lab/waterfall.html`，零依赖，~500 行）。这也更轻：单 pass 粒子云用不到 Three 的场景图。

渲染结构：40 万点，单 `drawArrays(POINTS)`；每粒子只有 `aSeed` 三个随机数，位置全部在顶点着色器里由 `uTime` 算，CPU 每帧只推 14 个 uniform，buffer 永不重建。生命周期 `u = fract(t·speed + seed)`：`u < uLip` 走湖面（`y = mix(uFarY, lipY, p^0.92)` + 行波），否则走瀑布（`fall = mix(q, q², 0.58)`，纯 q² 会把 20% 粒子挤在沿口 0.06 内烧成白带）。瀑布横向收窄成主流（`mix(1.02, 0.58, converge)`）才有重量感，铺满全宽只是水幕。

踩过的坑（都是视觉 bug，不是性能）：
- **条纹要用位置扭曲，不能用 alpha 调制**。`alpha *= 0.5+0.5*sin(x*k)` 得到的是"被调暗的粒子"，等距 `fract(seedA*34)` 更是直接变窗帘。正确做法是 `x += sin(x*k + q*a)*A`，`A·k→1` 时粒子真的聚成股、缝里没有粒子。
- **渐隐必须挂在生命周期上，不能挂在坐标上**。顶部用 `smoothstep(1.09,0.94,y)` 时，波浪把粒子推上去会让整列一起消失，留下黑柱。
- **湖面几何位移必须很小**（×0.22）。位移一大，俯视下立刻读成沙丘/雪原，怎么调参数都不像水；波纹应几乎全部体现在明暗上。
- 纯随机分布有泊松空洞，同样粒子数显得稀得多；横向改分层采样（lane + jitter）才连成"面"。
- 粒子数 18 万不够（1200×900 覆盖率仅 0.27），40 万才成面。

当前质感判断：结构（湖面/水沿/汇聚瀑布）成立，但整体偏"雪原/丝绒"，不够"水"。已试过加青蓝（`uColorTip=[0.34,0.74,0.88]`）略有改善。**未接入 SettingsPage**，铺开所需的 `.settings-content` 内联材质覆盖（`getPanelStyle()` 注入 backgroundColor/backdropFilter，CSS 盖不住）也尚未动。

### 方向转向：用户否决瀑布，改要"粒子布"

用户原话："不要瀑布了，要的是一块由一颗颗大粒子组成的布，上面有弯曲，在滑动、飘动"。所以 `waterfall.html` 的构图**整体作废**（保留作技术参考），新试验台是 `apps/desktop/lab/cloth.html`。

Cloth 的实现要点（三个坑都踩过）：
- **规则网格**而非随机分布：布需要"织理"，随机点永远读成星空。间距固定为 CSS 像素（`gap`），粒子直径取 `gap*0.52`，任何窗口尺寸下织理一致。
- **深度必须抬到屏幕纵轴**。只把起伏映射成景深缩放（`size *= persp`），画面上只表现为"变大变小"，永远是一块平板；必须 `screen.y = (b.y + z*k) * persp` 才是斜俯视的弯曲。
- **屏幕位置要走等比坐标**。`screen.x = p.x * aspect * ...` 会让 x 方向比 y 多拉长一个 aspect，网格被拉成竖线、布变成丝绒窗帘。正确结构：`b = 等比屏幕坐标`、`w = b * vec2(aspect,1)` 只给波形用，屏幕位置只吃 `b`。
- 振幅与波长要平衡：波长过长 → 飘带；振幅过大或高频项太多 → 山峰峡谷。当前 `height()` 用 3.40/3.00/5.20/7.80 四档，位移系数 0.40，透视 0.18。
- 布要比视口大 1.7×，否则弯曲会把侧边/底边翻进画面露出硬边。
- 波峰处粒子重叠，alpha 给满会烧成死白，上限压到 `0.50 + 0.42*near`。

浅色模式：白粒子必须在**中浅灰蓝**底（`#dde5eb→#bcc7d1`）上才托得住，近白的底会让白粒子完全消失。当前观感偏"霜/浮雕"，淡雅但对比弱。

### 追加：昵称改为淡入淡出

用户要求补过渡动画。**宽度不能进动画**：让 `max-width` 参与过渡会在整个过渡期切出半截字（实测中间帧 `opacity 0.74` 时第二个字被垂直切掉），正是 fit 判定要避免的产物。改为「布局瞬时、透明度做运动」：

- 名字元素常驻（`v-if="nickname"`，不随 fit 结果挂载/卸载），否则没有可淡出的对象；淡入终点由 JS 写入的 `--profile-name-max`（实测自然宽度）封顶。
- 淡入：`max-width` 用 `0s` 直接到位 + `opacity` 180ms 0→1，文字自始至终完整。
- 淡出：`opacity` 180ms 1→0，`max-width`/`margin-left` 用 `0s linear 0.18s` 延迟到淡出结束才收，所以看到的是完整名字在变暗。
- `prefers-reduced-motion` 取消过渡。

验证方式也换了：页面内 rAF 采样（CDP 轮询太粗）+ **不能靠 pause 动画取中间帧**——把处于 delay 阶段的 transition 暂停会丢掉 hold 值，测出来的盒宽是假的（先被这个骗了一次）。真实时间轴：淡入 7ms op=0.15 → 173ms op=1.00，宽度全程 24px；淡出 188→184px 时 op 1.00→0.58→0.17 且 width 恒 24，400ms 后才归零。行宽单帧大跳（切换折叠）时盒宽被行宽直接压到 0、看不到淡出——拖拽不会那样跳，别为此把宽度加进动画。

## 拖动把手诊断（未改动实现）

用户提出：左/右面板的拖动把手"整条都在面板里"，正常应该是半内半外。核实结论：**观察正确，且问题比视觉更严重——一半命中区是死的**。

- `.uie-column-resizer` 确实 8px 宽、`right:-4px`（几何上跨缝），但 `.uie-column` 是 `overflow: hidden`（UieColumn.vue L370），探出的 4px 被裁；**裁掉的部分不参与命中测试**。源码注释 L441 已自认"pill anchors fully inside the column"。
- 实测（逐像素复现这四条 CSS 用 elementFromPoint）：现行 4px 可命中且全在面板内；去掉裁切 8px 跨缝。空档 8px（presets `gap: 8`）里 elementFromPoint 落到 BODY，光标都不变。
- 佐证"这不是设计选择而是实现妥协"：同一文件里的垂直分割 `.uie-split-divider::after` 是**居中在分割线上**的，横向把手没跟着做，只因被 overflow 卡住。
- 修复思路（待用户拍板）：内容包一层 `inset:0; overflow:hidden` 内层、把手留外层不裁切（子元素都是 absolute，坐标不变）；命中区 8→12px；pill 骑在缝上。全仓无测试/组件引用 `uie-column-resizer`，改动自包含。
- 证据：`.tinadec_dev/evidence/2026-10-21-resizer-ownership/`（含 6 倍放大图与 hit-map.json）。探针一度想直接挂真实 UieCanvas，被 xterm/highlight.js 的 CJS interop 拖住，改用最小复现页更快。
