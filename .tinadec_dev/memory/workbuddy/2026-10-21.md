## 侧栏「新建工作区」加号常显修复（提交 8b83fce3）

用户报告：左侧边栏工作区块的加号本应鼠标靠近才出现，实际一直显示。

根因是级联而非悬停逻辑：`styles.css` 里 `.workspace-section-add { opacity: 0 }`（~L2010）
与 `.sidebar-extra { opacity: 1 }`（~L2260）**特异性相同**（各一个类），后者更靠后 →
「默认隐藏」被整条覆盖；原来那条 `:hover` 规则只是重复设 `opacity: 1`，等于没有隐藏态。
这是 `.sidebar-extra`（折叠导轨那版加的）引入的回归，`git log -L` 能直接看出来。

改法：
- 模板把 `.workspace-section-heading` 与 `#sidebar-workspaces` 包进新的 `.workspace-section`，
  悬停区域 = 标题 + 列表（用户要求「靠近工作区列表才显示」）；`.workspace-section` 接管
  `flex: 1 / min-height: 0`，`.sidebar-list` 保留自己的滚动端口，折叠时底部区域仍被钉住。
- 隐藏态改为 `.workspace-section .workspace-section-add`（0-2-0）显式压过 `.sidebar-extra`，
  不靠书写顺序；并加 `pointer-events: none`（以前加号看不见却仍能点中）。
- 折叠箭头仍只跟随标题行。

验证手段值得复用：`happy-dom` 可以按真实级联求 `getComputedStyle`（`:hover` 不求值）。
用 `<style>` 注入整份 `styles.css` + 最小 DOM，即可对照「修复前 opacity=1 / 修复后 0」，
比跑整条 Electron 链路快得多。单文件 vitest 在本机必须 `--pool=threads`，默认 forks
worker 会超时（`Timeout waiting for worker to respond`），且 CLI 不认 `--poolOptions.*`。

## 工作区选项选择器 + 最近对话分组

侧栏头部「加号」左侧新增齿轮（`SlidersHorizontal`，`workspace-section-action` 与加号共用
同一套显隐），点击开原生 popover（沿用 `.sidebar-view-menu` 那套 invoker/`beforetoggle`
模式）。首项「最近对话」是 `role="switch"` 的行，开关写进 `useWorkspaceList` 的
`ListState.recent`（与 collapsed/order 同一个 localStorage 记录，默认 false）。

开启后 `#sidebar-workspaces` 顶部出现 `.recent-conversations` 分组：跨所有工作区（含自由
对话）按 `updated_at` 倒序取 8 条（`recentSessionRows`），每行带来源工作区名。**行数据来自
`workspaces` + `allSessions`**，不是直接扫 `props.sessions`——这样项目可用性/存储作用域过滤
和自由对话的判定只有一份定义；点行只发 `select-session`，项目由 `HomeController.setSelectedSession`
自己同步（它按 session.project_id 回填 selectedProjectId）。

两个坑：popover 要点 `ref` 才拿得到元素（`hidePopover()` 靠它，漏了就静默不关）；弹层正好盖住
列表顶部，所以选中后关闭并把焦点还给齿轮（与 `changeView` 一致）。面板宽度 236 在 JS
（`OPTIONS_MENU_WIDTH`）与 scoped CSS 各存一份——关闭态是 `display:none`，开之前量不到。
折叠轨（`sidebar-collapsed`）下该分组整体隐藏，因为标题行本来就在那里 `display:none`。

### 后续演进（a1a5ef6b / 51ab079d / f681e253，已取代上面部分描述）

- 选项面板从「单个 switch」改成 **`UiCheckbox` 复选列表，三项**：最近对话（`recent`，默认 false）、
  项目对话（`projectConversations`，默认 true）、自由对话（`freeConversation`，默认 true）。
  因为要连点多项，面板**不再选中即关**，原来那套 `hidePopover` + 焦点还原已删除。

  （全量）**，所以隐藏分组后对话还能从最近列表进——这是刻意分叉，别顺手统一。
- 用量图接上真数据：`lib/sidebarUsage.ts` 纯函数（7 天窗口、`reportedTokens` 缺失保持 null 不伪 0、
  峰值归一 + 4% 地板 + level 分级）；组件里 `loadTokenUsage` 用 `scopedApi` 钉住存储作用域、

## 活动视图（最近活动）

第四个工作区选项 `activity`（与 最近对话 / 项目对话 / 自由对话 并列、互不排斥，默认关）。
开启后列表里多出 `.activity-group`：每张卡片 = 一个会话的**最新一次 run**，两行布局——标题在上，
下面一行左边是状态（图标 + 文字，按 tone 上色）、右边是"时长 · 项目名"（项目只写名字不画图标）。
点卡片只发 `select-session`。

- 状态词表只能用 Core 的 12 态（`TinadecGateway/src/contracts/runStatuses.ts` 是 Gateway 侧唯一出处，
  明令禁止自造 running/ready 之类的词）。这里归并成 tone：`awaiting_approval|awaiting_delegate|
  awaiting_user` → awaiting；`planning|understanding|executing|replanning|reviewing|paused` → active；
  其余 completed/failed/cancelled 各自一档；**词表外的值一律 unknown**（"需要看 Core 的事实"）。
- **没有跨会话的活动端点**（`/api/v1/sessions/{id}/runs` 只有按会话版本，且不支持 limit），所以
  `useRecentActivity` 只对列表真正渲染的那 5 条会话各读一次，三条规矩压住开销：选项关 → 一次都不发；
  读到的 `updated_at` 没变 → 复用；超过 60s TTL → 兜底重读。`Promise.allSettled` 保证一个会话读失败
  不会清空其它卡片；`generation` + 存储作用域双守卫丢弃过期响应。
- 时长/相对时间走 `Intl.NumberFormat({style:'unit', unitDisplay:'narrow'})` 与
  `Intl.RelativeTimeFormat`，**不用为五种语言各加一套"分钟/小时"文案**。
- 纯函数在 `lib/recentActivity.ts`（tone 归并、时长、格式化），取数在 `composables/useRecentActivity.ts`，
  组件只负责渲染 + 30s 时钟（仅在选项开启时 tick，`activityNow`）。

两个坑：① 活动分组一开始放在 `const freeSessions` 之前，而 `allSessions` 读它 → setup 期求值直接
TDZ 崩溃（`Cannot access 'freeSessions' before initialization`），把 `freeSessions` 提到派生块里，
并把 composable 的 watcher 挪到 `onMounted` 才彻底稳；② `<label>` 包一个 `<button>` 不会转发点击，
所以选项文本点不动——给 `label` 加 `@click` 切换、给 checkbox 加 `@click.stop`（四个选项都改了）。

## 侧栏四区块：拖拽排序（44bcc724）

用户澄清了关键语义：最近对话 / 最近活动 / 自由对话 / 项目分组**都只是工作区里的四块**，排序就是这四块在
`#sidebar-workspaces` 内的先后，不是"整块工作区 + 三个开关"。

- `sectionOrder: SidebarSection[]` 与 `order` 存在同一个键（`tinadec.sidebar.workspaces.v1`），默认
  `['recent','activity','free','projects']`（等于改动前的渲染顺序）。`readSectionOrder` 丢弃未知 id、
  把缺失区块按声明顺序补末尾，旧记录升级后四块一定都在。
- 齿轮面板的每行就是一块：行 `@click` 切换、**右侧把手 `draggable` 是拖拽源**、整行 `@dragover/@drop`
  是落点（上下半区决定 before/after）。`Alt+↑/↓` 挂在行（事件从 checkbox 冒泡上来）等价排序。
- 渲染侧 `listItems` 把 `sectionOrder × 四个开关` 折成列表，**关掉的块保留槽位**，重开回原位。
  `v-for` 与 `v-if` 不能同挂一个节点 → `<template v-for>` 包三个互斥分支，且分支判定必须写成
  `item.kind === 'workspace'`（写 `v-else` 时联合类型收窄不到 `item.workspace`）。
- **自由对话退出 `order`**：`reorderableWorkspace(key)` 守卫让它的行级拖拽 / Alt+↑↓ 全部失效，
  `:draggable` 只为项目行开启；右键上移/下移改走 `stepSection('free')`。`reconcile` 仍以自由对话为锚，
  项目行之间照旧用 `order`。原有测试 `reorders workspaces, including the free conversation` 相应改写。
- 选项行从 `<label>` 换成 `div`（`<label>` 里放 `draggable` 把手不可靠，且 label 会吞 dragstart 语义），
  把手 `@click.stop`，否则拖拽手柄等于第二个开关。把手常显 `opacity .45`，hover/focus/drag 变 1。

测试：AppSidebar 40、useWorkspaceList 7（含区块顺序持久化 + 旧记录自愈）、useRecentActivity 7、
i18nParity 8，全绿；`vue-tsc --noEmit` 通过。未在真实 Electron 里目视拖拽手感。
