## RouterAPI 项目"加载出错"：SchemaBootstrapper 抢跑迁移导致永久挂载失败

**现象**：运行中的实例如载 RouterAPI（`C:\git\agent\RouterAPI`）报加载出错；Core 日志 `RouterAPI/.tinadec/logs/core.log` 从 2026-10-21T06:33Z 起每次挂载都在同一个地方失败。

**根因链**（不是数据损坏，是代码顺序缺陷）：

1. `AgentPackI18n`（`202610210001`）迁移用裸 `alter table <t> add column i18n_json text null` 给 5 张表加列（agent_definitions / agent_modes / mode_nodes / prompt_pipelines / prompt_versions）。SQLite 没有 `ADD COLUMN IF NOT EXISTS`，这个迁移天生不幂等。
2. `AgentConfigurationDbContext : ConfigurationProjectionDbContext`，所以每次经 `ConfigurationProjectionDbContextFactory` 建 context 都会先跑 `ConfigurationProjectionCoordinator.AttachAsync` → `DbContextSchemaBootstrapper.EnsureColumnsAsync`，按**当前 model** 给已存在的表补列——**不写 `__EFMigrationsHistory`**。
3. Core 启动期先做配置投影读取、后跑 `DbContextMigrationParticipant.MigrateAsync`。于是投影抢先把 5 个 `i18n_json` 列加上，迁移随后撞 `duplicate column name: i18n_json` → 整批迁移中断 → 后续 ModelHealth / ExplorationGraph / PlanLedger / ToolAttribution 全部无法应用 → scope 挂载失败。
4. 每次重试都在同一处失败，所以永久坏掉（列已在、历史永远缺）。

**硬证据**：`pragma table_info` 里这 5 列的声明类型是 `TEXT`（大写），而迁移脚本写的是 `text null`（小写）——SQLite 保留 DDL 原文大小写，说明列出自 bootstrapper 的 `property.GetColumnType()`，不是迁移加的。

**已做**：备份 `RouterAPI/.tinadec/data/tinadec.db.bak-20261022-0126`，补写 `__EFMigrationsHistory` 的 `202610210001_AgentPackI18n / 10.0.10` 一行（列已按 model 正确到位，语义等价）。剩余 4 个迁移已验证无冲突可顺序执行（exploration_*/model_health 表不存在、tool_executions 缺那 4 列、索引列 run_id 存在）。

**已修（代码根治）**：`ConfigurationProjectionCoordinator.AttachAsync` 现在在补列**之前**先应用该 context 的 pending migrations——`GetPendingMigrations().Any()` 才 `MigrateAsync`，成功后按 context 类型记进 `_migrationsSettled`，避免每次建 context 都查一遍 history（访问都在 `_gate` 内）。迁移因此重新成为 schema 权威，projection 只补"没有迁移声明的列"。回归测试 `ConfigurationProjectionMigrationOrderTests` 用"先迁到最新、再删 5 列 + 删 history 行"造出老库，断言首次投影读取后 history 与列都在、二次打开不再炸。

顺带修掉一个既有缺陷：`UserStorageIdentity.AcquireLease` 只 `catch (IOException)`，但 Windows 上对已锁定的 `.storage-identity.lock` 做 `FileShare.None` 打开抛的是 `UnauthorizedAccessException`，导致 `ConfigurationDocumentTests.UserStorageIdentityIsStableConcurrentAndNewRootsHaveIndependentSchemas`（12 路并发）必红灯。现在两种异常走同一重试。

验证：新增回归 1/1；`ConfigurationDocumentTests` + `DmaeaGraphSchemaReconciliationTests` 24/24（修锁前 23 通过 1 失败）。**编译必须用 `-c Release`**——运行中的 `TinadecCore.Api` 锁着 `bin/Debug`，Debug 构建会以 MSB3027 失败。

user scope 库（`AppData/Local/TinadecOffice/data/tinadec.db`）history 停在 `202610070001`、无 i18n 列、agent 表存在，属于正常待升级状态，代码修复后不会再踩坑。

## 默认配色偏青蓝：品牌色存在两套源

**现象**：用户报"默认出来的成果是青蓝色"，怀疑代码里有脏东西。

**根因**：仓库同时存在两套品牌色定义，而且 Monet（`lib/monetExtract.ts`）只接管其中一部分变量。

1. **CSS 兜底 = 品牌青蓝**（`styles.css`，dark 块）：`--accent-primary: #2ec4b6`(L175)、`--accent-brand: #2ec4b6`(L181)、`--text-brand: #2ec4b6`(L167)、`--accent-soft: rgba(46,196,182,.12)`(L184)、`--shadow-focus`(L189)；light 块是 `#1f8f80` / `#1f6f68` / `#9fcac0`(L256/261/249/244)。
2. **TS 默认 = 蓝**（`composables/useTheme.ts`）：`useStorage('tinadec-accent-color', 'blue')`(L203)，blue 的 dark `#58a6ff`(L47)。
3. Monet 只 emit 约 60 个变量（`buildDynamicVars` L106-244）。**`--text-link` 不在其中**：dark 是 `#2ec4b6`（青蓝）、light 是 `#0969da`（蓝）——同一语义两套色系，这条最像 bug。monetExtract 头部契约注释里明确把 `--text-link` 归为"语义色保持不动"，但它实际装的是品牌色。
4. 实测：seed `#58a6ff` → HCT hue 256.9 → tone80 `#a2c9ff`（浅蓝）。所以**正常情况下主色是蓝**，青蓝只出现在没接上变量的位置。
5. 其他硬编码青蓝：`useTerminal.ts` L93 `rgba(46,196,182,0.25)` / L117 `rgba(31,143,128,0.2)`（终端选中背景，改主题也不变）；`lib/shareBrand.ts` L34 `SHARE_BRAND_COLOR='#2ec4b6'`（分享卡品牌色，来自 favicon）；`NotificationIslandHost.vue` / `NotificationDetailDialog.vue` / `rendererErrorFallback.ts` 的 `var(--x, #2ec4b6)` fallback；debug/* 面板。
6. **一处类型混用**：`settings/sections/PersonalShareCard.vue` L81 `read('--accent', '#2ec4b6')`——`--accent` 是 shadcn 的 `H S% L%` 三元组（`210 40% 96.1%`），不是合法 CSS 颜色，塞进 canvas fillStyle 无效，只有变量缺失时才会落到青蓝 fallback。应读 `--accent-primary`。
7. 死字段：`useTheme.ts` L56-57 blue 预设的 `light.textBrand: '#17484d'`、`borderInputFocus: '#2e7d76'` 是青绿残留（当前只被 `dark.accentPrimary` 用作 seed/swatch，不影响渲染，但说明这套表是从青色方案复制来的）。

**待用户确认具体界面**：若他看到的是整体青蓝而非局部，要查 localStorage `tinadec-accent-color` 是否被设成 `dynamic` 而背景 `type:'none'`——`resolveAccentVars` 返回 null 时 `applyAccentColor` 直接 return，全部变量回落到 CSS 青蓝。
