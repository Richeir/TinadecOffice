## v0.4.0 第二次失败：Core prompt 哈希验证漏 overlay（真 bug，已修）
- **desktop-release.yml 的步骤顺序**：npm ci → Test Desktop → Typecheck → Test Gateway → **dotnet 定向测试（ConfigurationDocumentTests|StorageScopeApiTests）** → 打包。Test Desktop 自 10-22 起红，**dotnet 关卡在这版内容上从没执行过**——第二次发版才第一次跑到，立刻炸：`StorageScopeApiTests.AgentPacksAreGlobal_AndAProjectSessionUsesTheUsersPublishedMode` 三腿同炸，`PromptVersion content hash verification failed`。
- **根因（确定性 bug，本地复现）**：`AgentPackService.PublishPromptPipelineAsync` 安装时 `hash = SHA256(graph + "\n" + i18nJson)`（b9c9d7ca「ContentLength includes the overlay bytes」），而 `FormalModeResolver.VerifyHash` 只对 `GraphJson` 本体算——**pack 资源一带 i18n overlay 必炸**。GraphSeedPack 3.2.0（ArtEx）给所有 pipeline 加了五语言 overlay → v0.3.0 无 overlay 所以绿。Agent 侧没问题：i18n 嵌进 snapshot 再哈希。
- **修法**：resolver 侧按 overlay 条件拼验算体（`I18nJson is null ? GraphJson : GraphJson + "\n" + I18nJson`）——同时兼容两个手工写入点（AgentConfigurationService/Endpoints 都是 graph-only 且无 overlay）。提交 `fee69385`，发布说明「修复」段已补。
- 本地验证：StorageScopeApiTests 22/22；CI 关卡完整 filter 43/43；FormalModeSnapshotTests 4/4。
- 本地跑 dotnet 测试前要停掉占着 bin 的 dev 进程（TinadecCore.Api.exe / TinadecTools.exe，用户上午起的 dev server），MSB3027 文件锁——**已 kill，需要时让用户重启 npm run dev**。
- 第三次发版：tag v0.4.0 → fee69385，create-version success，desktop-release run 39890975036 监视中。
- 教训④：**desktop-release 的 dotnet 关卡在 Test Desktop 之后**——上游步骤红会级联遮住下游，修一个红灯后要预期下一个原来从没跑过的关卡可能接着炸；发版前最稳的做法是本地把每道关卡的命令原样跑一遍（vitest 全量、node --test 全清单、dotnet 关卡 filter、bun test gateway）。

## v0.4.0 第三次失败：Linux 冒烟 socket 路径超限（边界翻转，已修）
- 第三次 run：**win-x64 / osx-arm64 全绿**（测试、dotnet 关卡、打包、冒烟全过），只剩 linux-x64 倒在 `Smoke test the packaged application (Linux)`：`FATAL:chrome/browser/process_singleton_posix.cc Socket path too long`（SIGTRAP，Core 没起来）。
- **根因**：Chromium 单例锁是 Unix socket（user-data-dir 下，超长时 fallback 到 `TMPDIR/scoped_dirXXXXXX/SingletonSocket`），上限 108 字节。冒烟根目录在仓库深处 `.runtime-cache/packaged smoke <pid>/temp/...`，在 GitHub runner 的深路径下拼出约 133 字节。**脚本自 v0.3.0 没改过**——路径深度贴着边界，PID 位数和 scoped_dir 随机后缀翻过去就炸（v0.3.0 运气好）。
- **修法**（`d517d7cd`）：smokeRoot 默认改到 `os.tmpdir()`（`/tmp/tinadec-packaged-smoke-<pid>`），user-data/profile/TMPDIR/全部 socket 路径缩到 ~68 字节；`TINADEC_SMOKE_ROOT` 仍可覆盖。smokePosix.test.mjs 12/12。Windows 冒烟脚本不动（命名管道无此限制，win 本就绿）。
- 第四次发版：tag v0.4.0 → d517d7cd，desktop-release run 39893212992 监视中。
- 教训⑤：**贴着平台限制（socket 108 字节这类）的路径布局是隐形炸弹**，测试环境"从没变过"不代表下次不炸；涉及 TMPDIR/user-data-dir 的要主动算路径长度。
- 四次发版的红灯谱：①vitest 12 例（过时期望+mock 缺口）→ ②electron fixture 白名单（被 vitest 遮住）→ ③Core prompt 哈希漏 overlay（真 bug，被遮住）→ ④Linux 冒烟路径超限（边界翻转）。一层洋葱。
