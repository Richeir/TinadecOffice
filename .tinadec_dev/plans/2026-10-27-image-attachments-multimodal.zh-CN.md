# 图片附件多模态链 + 工作空间一等资源

日期：2026-10-27

## 产品结论

工作空间不是“附件暂存区”，而是一份用户可审阅、Agent 可执行的资源授权清单：

- 目录是递归资源授权，继续使用 `project.toml` 的 `[[workspace.roots]]`。
- 单文件是独立的精确资源授权，使用 `[[workspace.files]]`；它引用原文件，不以复制替代授权。
- 会话附件是“Agent 看过什么”的交付事实，不是第二套目录权限。附件被模型真实接收后才标记 `delivered_to_model`。
- 工作空间面板同时展示目录授权与会话曝光。用户可以分清“Agent 有权访问什么”和“Agent 实际看过什么”。

## 安全边界

- `project.toml` 只表达期望；宿主注册表 `projects.toml` 的 `authorized_roots` / `authorized_files` 才是授权来源。
- 单文件授权只能读写该精确路径，不能推出父目录权限。
- 符号链接、重解析点、产品存储目录、相对路径和不存在的文件在准入时拒绝。
- 改动在 run 准入时冻结，并进入 TinadecTools 进程键；只影响新 run。
- 添加资源不放宽审批门。写文件仍受冻结权限模式和逐次审批约束。

## 实施段

1. **工作空间文件授权**：扩展 WorkspaceDefinition、宿主注册、ToolExecutionContext、TinadecTools 文件边界和工作空间卡片。保留目录拖入；文件拖入提供“绑定原文件”和“附到当前对话”，不再只有复制。
2. **附件一等事实**：`message_attachments` 增加来源、项目路径和送达事实；新增项目曝光查询。Composer 附件默认记录当前项目，不伪装成工作空间文件授权。
3. **多模态管线**：模型能力声明、图片预算、DataContent 组装和送达标记。只有触发消息绑定的附件进入该 run；后续 run 依赖文本引用。
4. **桌面产品面**：工作空间面板的文件/目录分区、曝光分区、拖放分流和“附到当前对话”预填。
5. **验收**：Core 定向测试、契约再生成、Desktop 类型检查/定向测试/构建，以及可用时的真实视觉模型验证。

## 明确非目标

- 不把历史图片在每个后续 run 重放。
- 不把 steering 变成附件投递通道。
- 不因添加目录或文件而跳过审批。
- 不声称 Core 能证明客户端声明的源路径就是字节的真实来源；Core 校验路径形状、项目归属和当前授权事实。
